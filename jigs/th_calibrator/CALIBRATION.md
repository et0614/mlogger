# 温湿度・CO2 プローブの一斉校正手順 (th_calibrator)

治具 th_calibrator (1 台 64 スロット) と `python/thc_client.py` を使い、温湿度・CO2 プローブ
(mlogger_th_sensor) を一斉に校正する手順。治具を 2 台使う場合は、治具ごとに `--port` を指定して
別々に実行する。

| 項目 | 方法 | 係数の保存先 |
|---|---|---|
| 乾球温度・相対湿度・グローブ温度 | 恒温恒湿槽で 3 条件を計測し、オフセット B を設定 (A = 1 固定) | プローブの EEPROM |
| CO2 | 密閉容器で安定させた後、強制校正 (FRC) | STCC4 内部 |

---

## 1. CO2 の校正 (FRC)

### 1.1 予熱が必要な理由 (STCC4 データシートより)

**FRC の直前の 30 秒だけでは足りない。** FRC の前に長時間の運転が必要になる。

| データシートの節 | 内容 |
|---|---|
| 3.4.15 perform_forced_recalibration | FRC の直前に最低 30 秒の連続測定 (または single-shot 30 回)。この手順の間、センサの読みと CO2 濃度が安定していること |
| 1.1.3 Warm-Up | 3 時間以上止まっていた後は、精度が出るまでに最大 1 時間の連続測定、または single-shot 360 回 |
| 1.1.4 Initial Operation | 新品を初めて使うときは、最大 12 時間の連続測定と、その後の外気 (約 400 ppm) への暴露が必要。動作開始から 1 時間以内に電源を切ると、初期化のタイマーがリセットされる |
| 3.4.6 measure_single_shot | single-shot の間隔は 5〜600 秒を推奨 (自動校正 ASC を正しく動かすため) |

プローブのファームは、FRC コマンドを受けると 30 秒の連続測定を行ってから FRC を適用する
(3.4.15 の直前の最低条件)。**それ以前の予熱は、校正者が運転して済ませておく必要がある。**

参考: 電源投入時の conditioning (約 22 秒) の直後は、CO2 値が +300 ppm 以上高く出て、
落ち着くまで 30〜60 秒かかることを実測している。

### 1.2 手順

1. **プローブを治具に挿し、電源を切らずに予熱運転する。**
   ```
   python thc_client.py --port COM5 monitor --interval 5
   ```
   - 最低 30 分 (single-shot 360 回) 運転する。
   - 新品のプローブは、可能なら数時間〜一晩運転する。
   - **途中で抜き差ししたり治具の電源を切ったりすると、予熱が最初からになる。**
   - 間隔は 5 秒以上にする (`monitor` の既定値 3 秒は、データシートの推奨より短い)。
2. **予熱の後半は、密閉容器の中で CO2 濃度を安定させる。**
   安定の確認は目視ではなく記録で行う。
   ```
   python thc_client.py --port COM5 log --out co2_before.csv --interval 5 --keep-coef
   ```
   10 分程度の間に、値が一方向に動き続けていないことを確認する。
   (`--keep-coef` を忘れると、温湿度の補正係数がリセットされるので注意)
3. **`monitor` / `log` を Ctrl+C で止め、基準器の値で FRC を実行する。**
   ```
   python thc_client.py --port COM5 frc 1000
   ```
   - 受け付けるのは 300〜5000 ppm。
   - Ctrl+C で止めてもプローブの電源は切れないので、予熱はリセットされない。
   - **FRC が終わるまでの約 35 秒間は、容器を開けず濃度を一定に保つ。**
   - conditioning 中 (`cond` 表示) のプローブは、それが終わってから FRC を始める。完了は
     コマンド側で待つ。
4. **FRC の後に検証する。** 再び `log` で 10〜20 分記録し、基準器と合っているかを確認する。

FRC の直前の 30 秒 (プローブのファームの `FRC_WARMUP_SECONDS`) は、上の予熱を済ませていれば
データシートの条件を満たす。検証で系統的なずれが残る場合は、この値を延ばすことを検討する
(プローブ全台の書き換えが必要)。

## 2. 乾球温度・相対湿度・グローブ温度の校正

グローブ温度はグローブ球を外した状態で校正する (時定数は乾球温度と同じになる)。

### 2.1 恒温恒湿槽の条件

- 3 条件: **20°C / 70%RH、25°C / 50%RH、30°C / 30%RH**
  - 室内の温熱環境をカバーし、SHT40 の精度が最も良い範囲 (25〜75%RH) に収まる。
  - 80%RH を超える高湿は、SHT4x のオフセットが一時的にずれることがあるので避ける。
- **基準値は、校正済みの温湿度計をプローブの近くに置いて取る** (槽の表示値は基準にしない)。
  可能なら治具ごとに基準器を置く。
- 条件は湿度が単調に変わる順に進める (30% → 50% → 70%、またはその逆)。
- 設定値に到達してから 30〜60 分待ち、落ち着いた後の 10〜15 分間を平均に使う。
- 通電中の治具基板の熱がプローブに届かないよう、槽内の気流を確保する。

### 2.2 手順

1. **記録する。** 開始時に、全台の係数が A = 1, B = 0 にリセットされ、生値が記録される。
   ```
   python thc_client.py --port COM5 log --out jigA.csv
   ```
   CSV の先頭 3 行は sensor_id / board_ch / item の見出しで、1 台につき t, rh, glb, co2 の 4 列。
   読めなかった値は空欄になる。
2. **Excel で B を求める。** 条件ごとに安定区間を平均し、B = 基準値 − 計測平均 を 3 条件で平均する。
   3 条件の間で B がばらつく個体は不良を疑う。
3. **B を書き込む。** CSV の形式は次のとおり。
   ```
   sensor_id,t_b,rh_b,glb_b
   3812345,0.12,-1.50,0.05
   2290111,,2.10,
   ```
   ```
   python thc_client.py --port COM5 set_coef offsets.csv
   ```
   - sensor_id は 10 進数 (16 進数だと Excel が数値に変換してしまう)。
   - 空欄の項目は書き換えない。
   - 許容範囲は温度・グローブが ±3.0、湿度が ±9.99。範囲外の値や ID の重複があると、全体を
     書き込まずに中止する。
   - 書き込み先はセンサ ID で照合し、書き込み後に読み戻して確認する。治具 2 台分を 1 つの CSV に
     まとめてよい。
4. **確認する。** `coef_show` で係数を確認し、1 条件だけでも記録を取り直して、補正が効いているかを
   見る。
   ```
   python thc_client.py --port COM5 coef_show
   python thc_client.py --port COM5 log --out verify.csv --keep-coef
   ```

---

## 3. 注意事項

- **`log` は開始時に係数をリセットする。** 書き込み後に記録するときは必ず `--keep-coef` を付ける。
- `--duration` の単位は分 (2 日間なら 2880)。
- 長時間の記録で読み出しが失敗しても、その周期を飛ばして記録を続ける (`datetime` 列の欠けで
  分かる)。
